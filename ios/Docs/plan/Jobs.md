# Plan — `Jobs/` (Batch 0, one owner)

Interfaces: `INTERFACES.md` → Jobs/. Design: `ARCHITECTURE.md §2.4`. This folder is the cloud-first
spine; every feature store depends on it and none polls on its own.

| File | Purpose | Behaviour | Read |
|---|---|---|---|
| `Jobs/JobKindSpecs.swift` | the per-kind table | Cadence ladders, background intervals, deadlines, `cancelable`, `unknownReadsBeforeTerminal`, `usesSSE` exactly as the §2.4 table. | `server-chat-jobs-chats.md §3.2 (cadence)`, `web-code-ux.md §3.3`, `web-agent-ux.md §5`, `web-media-ux.md §8` |
| `Jobs/JobPointerStore.swift` | `jobs.json` via `DiskStore` | Array of `JobPointer`; ≤ 40 (drop oldest terminal-less beyond deadline); filtered by `ownerID` on read; write on every change (debounced 200 ms); never a transcript. | `audit-ios-chat.md §Major M14` |
| `Jobs/JobWatcher.swift` | one loop per pointer | Rules (1)–(9) of §2.4: offline pause (`NetworkMonitor.updates`), `Backoff(1.2, 30)`, 20 consecutive transport errors → `.reconnecting` + 30 s, 401 → suspend + `session.handleUnauthorized`, 403 → forget, 404-with-body → failed, deadline → `.expired`, `unknown`×N per spec, `BackgroundHold` while active in background with cadence ×2, SSE first when `spec.usesSSE` with poll fallback on stream error, progress throttled ≤ 10 Hz and only when `text.count` grew or phase changed. Emits to the manager on the main actor. | `server-chat-jobs-chats.md §3.2–3.3`, `server-agent.md §8, §12.2`, `server-media.md §0.6` |
| `Jobs/ChatJobDriver.swift` | chat/longdoc/longfile/codebuild/brainask | `read`: `GET /api/chat/job?id=` → phase mapping; `failed` + `status ≥ 400` + JSON `error` → `.refused`; `failed` + `cancelled`/`499` → `.cancelled`; `failed` other → `.failed(code:, partial:)` (codebuild keeps any parseable `firas-project` fence in `text` as partial); `unknown` → `.unknown`; `cancel` → `POST /api/chat/cancel` (409 → false for queued chat = local stop). | `server-chat-jobs-chats.md §3.2–3.5`, `server-code-brainask.md §1.7, §2.7, §3.4` |
| `Jobs/AgentJobDriver.swift` | agentrun | `stream`: SSE `snapshot` → `.running(JobSnapshot(agent:))`, `terminal` → one final `read`, `agent-error {retryable:false}` → `.terminal(.failed)`; reconnect 1 → 15 s doubling then poll fallback. `read`: `GET /api/agent/job` → `{job:null}` counts toward `unknownReadsBeforeTerminal` (2); `done` → completed, `fail` → failed(code = `error` or `task_failed`); 503 `storage_unavailable` = transient. `cancel` always returns false. | `server-agent.md §7, §8, §9, §12.2, §14` |
| `Jobs/MediaJobDriver.swift` | image/video/music | `read`: `GET /api/{kind}/job?id=` → `done` → completed with `mediaKey = key ?? id`, `fail` → failed(code = `error ?? reason ?? "engine_failed"`), `running`/`queued` → running; a lost id answers `running` forever, so the deadline is the only exit (`.expired`, pointer kept for one later check on next launch). `cancel` false. | `server-media.md §0.6, §1.2, §2.2, §3.2, §6` |
| `Jobs/JobManager.swift` | the registry | `startChatQueueJob`: persists the pointer **before** returning; replay answering `completed` → observer `didFinish(.completed)` directly; `failed + retryRequiresNewCid` → `.failed` immediately (no watcher). 409/429/403/413 on start are thrown as `APIError` for the store's `ErrorPresenter`. Terminal delivery order: observer → landed? → `CompletionCue.fire` (active, `!callActive`) or `NotificationManager.postJobTerminal` (inactive; `notified` flag) → `forget`. `refreshOnce`: task group with a 20 s deadline, one read per pointer, notifications for terminals, returns whether anything is live. `applicationDidEnterBackground`: hold + `BackgroundRefresh.schedule(after: 60)` when pointers exist. `resumeAll(owner:)` on `.active` and after `restore()`. `liveCount(product:)` drives sidebar dots and Agent badge. | `ARCHITECTURE.md §2.4`, `web-agent-ux.md §10`, `server-code-brainask.md §2.6` |
| `Jobs/BackgroundRefresh.swift` | `BGAppRefreshTask` | `identifier = AppConfiguration.bundleID + ".jobs"`; `register` must run inside `didFinishLaunching`; handler: `task.expirationHandler` cancels the group; calls the registered async handler; `setTaskCompleted(success:)`; resubmits when the handler returns true. `schedule` swallows `BGTaskScheduler` errors (simulator/sideload may refuse). | `audit-ios-shell-settings-design.md §2.1 F2` |

Rules: no store polls; drivers never touch UI; every await inside a watcher is bounded by the
`.poll` budget; `JobManager` methods that mutate `pointers` are the only writers of `jobs.json`.
